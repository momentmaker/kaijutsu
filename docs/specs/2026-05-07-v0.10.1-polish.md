# v0.10.1 — polish patch

**Status**: Stages 2 + 3 shipped; Stage 1 deferred to v0.11.0 (extraction scope: 470 LOC of cobra-coupled logic, larger than fits a polish patch)
**Date**: 2026-05-07
**Type**: patch (closes v0.10 stub gaps + applies Tier A/B from agent-native CLI audit)

---

## Why

v0.10.0 shipped the eval runner with two known stubs (loud-warned via stderr) + a CI workflow scoped to "harness gate only" because live judge dispatch needed secrets-injected `ANTHROPIC_API_KEY`. Two issues with that direction:

1. **CLI > API key for users**. The `claude` / `codex` / `gemini` CLIs route requests through whatever subscription tier the user has authenticated locally — the API keys we'd inject in CI are a separate billing channel that costs extra on top of those subscriptions. v0.10's local `jutsu eval skill` already prefers the CLI driver. The CI ambition (pay for judge dispatch via API) conflicts with that principle: users who chose paid CLI access shouldn't be silently re-charged via the API path.
2. **Stage 2 stubs feel half-built**. `eval preset` + `eval swarm-skill` warn at runtime that they dispatch claude regardless of `<preset>:<mode>`. Real `swarm.runSwarmPipeline` integration was deferred to v0.10.x; users running these subcommands today get green output but meaningless signal.

Concurrently, the Tier-A/B subset of the agent-native-CLI audit (`/Users/rubberduck/GitHub/momentmaker/kaijutsu` ad-hoc audit against trevinsays.com/p/10-principles-for-agent-native-clis) is cheap + mechanical:

- `--dry-run` missing on `install`/`upgrade`/`remove`/`publish` (post principle #4)
- Error messages reject enum values without naming the valid set (post principle #3)

Bundle these into v0.10.1.

## Build sequence (3 stages)

### Stage 1 — Stage 2 stub replacement + CI doc pivot

**Goal**: `eval preset` + `eval swarm-skill` invoke real `swarm.runSwarmPipeline` per side. Stub stderr warning removed. CI workflow comment updated to document the harness-gate-only design as intentional + permanent (not deferred).

**Refactor needed**: extract `runSwarmPipeline` (currently in `cli/internal/cli/swarm.go`, ~470 LOC, takes `*cobra.Command`) into a non-cobra core. Likely shape:

`cli/swarm.go::runSwarmPipeline` becomes a thin wrapper that maps cobra → `PipelineOpts` and calls `swarm.RunPipeline`. `eval preset` + `eval swarm-skill` resolvers also call `swarm.RunPipeline` directly with their own `PipelineOpts`.

- `jutsu eval preset` without `--evals` still rejects with the v0.10 cobra `MarkFlagRequired` error (shipped in Stage 2 squash); the validation contract is preserved during the refactor.

### Stage 2 — `--dry-run` sweep

**Goal**: `--dry-run` flag on `install` / `upgrade` / `remove` / `publish`. Prints planned mutation set + exits 0. No filesystem writes, no lockfile updates, no PR creation.

**Output shape (markdown TTY, JSON pipe — auto-flip)**:

```
$ jutsu install pr-review --dry-run
[dry-run] would install pr-review@1.2.0 (sha=abc123, signed by kaijutsu-core@github)
[dry-run] would write:
  - .claude/skills/pr-review/SKILL.md
  - .claude/skills/pr-review/scripts/...
[dry-run] would update kaijutsu.lock.json: + pr-review@1.2.0
[dry-run] no permissions prompts triggered (skill declares fs-write: scoped)
```

**Success criteria** (specific, testable):

- `jutsu install <skill> --dry-run` exits 0; `.claude/skills/<skill>/`, `.agents/skills/<skill>/`, `kaijutsu.lock.json` all unchanged on disk after invocation (test: `os.Stat` returns ENOENT or pre-existing mtime).
- `jutsu upgrade --dry-run` prints the diff preview but does not rewrite the lockfile or any skill dir.
- `jutsu remove <skill> --dry-run` leaves the skill dir + lockfile entry intact.
- `jutsu publish --dry-run` does NOT invoke `gh pr create`. Stage 2 test mocks `gh` (already present in `publish_test.go` — extend) and asserts zero invocations.
- Non-dry-run behavior across all four commands stays byte-identical to v0.10.0 (existing tests still green).

**Key files**:
- `cli/internal/cli/install.go`
- `cli/internal/cli/upgrade.go`
- `cli/internal/cli/remove.go`
- `cli/internal/cli/publish.go`
- per-command `*_test.go` — add dry-run case for each

## Risks

| Risk | Mitigation |
|---|---|
| `runSwarmPipeline` extraction regresses v0.6+ behavior | Heavy unit-test pass before refactor; integration test runs the existing `jutsu swarm pr-review` end-to-end pre + post extraction; diff outputs |
| `--dry-run` skips a side-effect that *should* happen even in dry-run (e.g. permissions prompt) | Be explicit per command: dry-run skips ALL side effects including prompts. Dry-run is "tell me what would happen" |
| Error sweep ambiguity — what counts as an "enum"? | Define narrowly: any error that rejects a value because it's not in a closed set. Open-set errors (file paths, refs) excluded |
| Bundle is too big for a patch | If Stage 1 extraction balloons past expected scope, ship Stages 2+3 as v0.10.1 and Stage 1 as v0.11.0 |

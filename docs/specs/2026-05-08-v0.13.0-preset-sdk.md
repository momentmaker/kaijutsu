# v0.13.0 — Preset SDK (swarm.yaml per-project + per-user)

**Status**: draft
**Date**: 2026-05-08
**Type**: minor (additive — new yaml-driven preset surface; built-in presets unchanged)

---

## Why

kaijutsu currently ships 10 built-in swarm presets (pr-review, doc-review, brainstorm, dream, refactor-plan, security-audit, reverse, test-gap, bug-repro, code-archaeology). Adding a new preset is non-trivial work — a v0.12 Tier A preset PR shipped roughly 200 lines of Go (preset definition + cobra subcommand + tests) plus a CHANGELOG entry plus a doc-review pass. The exact figure varies by preset shape; the point is that the catalog can only grow at the rate of project commits to this repo, and user-specific lens combinations can't ship at all without forking.

A `jutsu swarm dream --mode full --lenses all` adversarial pass on the v0.13 candidate set surfaced 3-agent consensus that the **real user pain is lens routing, not lens authoring**. Quote: "Ship Preset SDK FIRST. Presets compose personas → routing answer to authoring overload. Reverse current ordering." The dream also flagged 4 lens-blindspot warnings worth tracking (RLHF convergence, status-quo bias, model-shared adversary archetypes, time-lens IDE-subsumption forecast).

v0.13 ships the smallest-surface SDK that lets users compose their own presets without forking the repo:

- **`.kaijutsu/swarm.yaml`** (per-project) — checked into the repo for shared team presets.
- **`~/.kaijutsu/swarm.yaml`** (per-user) — for personal lens combinations across projects.
- Each user-defined preset becomes a `jutsu swarm <name>` cobra subcommand at root construction time.
- No registry, no signing, no `jutsu install <preset>` — local-file-only trust model (symmetric with `agents.yaml`).

Spec: this doc. Plan: `IMPLEMENTATION_PLAN.md` (3 stages).

## Locked decisions

| # | Decision | Choice |
|---|---|---|
| 1 | Config locations | `.kaijutsu/swarm.yaml` (project, primary) and `~/.kaijutsu/swarm.yaml` (user, optional). Project wins on collision (matches `agents.yaml` precedence). |
| 2 | Built-in shadowing | **Hard error.** A user preset named `pr-review` is rejected at load time with the existing enum-rejection format ("preset name conflicts with built-in `pr-review`. Pick a different name. Built-ins: ..."). No silent override. Built-in names are the contract; if a user wants different behavior, they pick a different name. |
| 3 | Custom auxiliary input plumbing | **Explicitly NO.** v0.12 presets like `test-gap`/`reverse` bake `--tests`/`--spec` content into the prompt at the cobra layer (Go code). v0.13 swarm.yaml composes existing 3 InputKinds (diff/files/prompt) only. Users CANNOT define new flag types in yaml. If a user genuinely needs custom auxiliary input, that's a Go-coded preset PR — not a yaml entry. Keeps the schema small + the trust surface tight. |
| 4 | Field set | Each user preset entry exposes the same Go-struct fields the built-in presets use, with these exact contracts: `name` (non-empty, no whitespace, must not collide with a built-in per Decision #2), `description` (non-empty, single line), `inputKind` (string enum: `diff` / `files` / `prompt` — exactly one), `defaultPrompt` (non-empty string; MUST contain exactly one literal `%s` slot — the cobra layer substitutes the input body via `fmt.Sprintf` at dispatch time), `synthesizer` (non-empty string; MUST contain exactly one `%s` slot — substituted with the per-agent findings JSON), `severityVocab[]` (non-empty list of strings; each value MUST match an existing `swarm.Severity` constant — no custom severity strings; predefined set: `blocker`, `issue`, `minor`, `info`, `critical`, `high`, `medium`, `low`, `informational`, `recommended`, `alternative`, `risky`, `speculative`), `mode` (string enum: `quick` (default) or `full`), `personas[]` (list of strings; each MUST resolve in `agents.yaml`; default empty = legacy auto-detect), `confidenceFloor` (float, 0.0–1.0; default 0.0). **NO `perAgent[]` map** (per-agent specialization is the v0.14+ Persona SDK gate per Out-of-scope below; both v0.13.x and v0.14+ refer to the SAME deferral — they are the same feature, not two). **NO `debate` template** (uses `genericDebateTemplate` from v0.12). |
| 5 | Cobra registration | Dynamic — at root cmd construction, load both yamls, register each user preset as a subcommand under `jutsu swarm`. Per-InputKind flag wiring reuses existing patterns: InputDiff = `--pr/--diff-from-branch`, InputFiles = positional paths, InputPrompt = positional prompt. `commonSwarmFlags` binds the shared options. |
| 6 | Reload semantics | Re-read on every invocation. No `install` step, no file watcher, no SIGHUP. Yaml parse errors → stderr warning + skip user presets entirely, NOT hard-fail (otherwise a malformed yaml breaks all swarm commands including built-ins). **Intra-file duplicate names** (two presets with the same `name:` in the same yaml file) are a validation error — the entire FILE is rejected with a citation of the duplicate; the OTHER yaml file (project vs home) still loads. Avoids ambiguity about which entry "wins" within one file. Cross-file collisions resolved by the project-shadows-home rule (Decision #1). |
| 7 | Schema validation | Ship `schemas/swarm.schema.json`. New `jutsu swarm validate` cobra command schema-validates `.kaijutsu/swarm.yaml` (or path arg). Surfaces field-by-field errors before users hit them at command time. |
| 8 | Help-text discoverability | `jutsu swarm --help` differentiates user presets from built-ins. Each user-preset row in the AvailableCommands block tagged `[user:project]` or `[user:home]` so users see at a glance which presets came from where. |
| 9 | Persona references | User preset's `personas[]` references existing agents.yaml personas (built-in or user-defined). Unknown persona name → existing enum-rejection error at command time (per the v0.10.1 "error enumeration sweep" — see `cli/internal/cli/error_enum.go::listPersonas`; format: `--personas: persona %q not found. Defined personas: <list>`). |
| 10 | Reference implementations | Ship 3 example swarm.yaml files at `docs/examples/swarm/`: `concise-pr-review.yaml`, `deep-test-gap.yaml`, `legacy-audit.yaml`. Each is a real, copy-paste-able starter. README v0.13 section points users at these. |
| 11 | Marker bump | `0.12.0` → `0.13.0` in `init_agents_fragment`. |

## Out of scope (defer to v0.13.x or later)

- **Persona SDK** (cross-agent personas, persona authoring wizard, `jutsu agent persona new/test/lint`). Reordered to v0.14+ per dream consensus that real pain is routing not authoring. v0.13.x will add **read-only persona browse** (`jutsu agent persona browse` — list curated built-ins + community examples for paste-into-agents.yaml) as the 80%-benefit / 5%-effort path.
- **Persona-as-skill**: dream flagged as category error. Will not ship.
- **Per-agent prompt specialization** (the `perAgent[]` map). Same feature as the Persona SDK item above — they're not separate work items. Defer to v0.14+ as a single decision gated on (a) user data showing shared prompts collapse to identical outputs AND (b) cross-corpus diversity A/B evidence (the v0.12.x benchmark commitment).
- **Custom `debate` template per user preset.** v0.13 uses `genericDebateTemplate` (v0.12 addition). Custom debate prompts are a v0.14+ candidate.
- **Custom InputKind plumbing** (auxiliary `--tests`/`--spec`/`--git-log` flags from yaml). v0.13 = compose, not extend (Decision #3).
- **Sharing / marketplace / preset registry**: no `jutsu install <preset>`. Sharing = copy-paste yaml or `git` of the file. Symmetric with how `agents.yaml` is shared today.
- **Hot-reload / file watcher.** Re-read happens on next `jutsu swarm` invocation (Decision #6). No SIGHUP.
- **`jutsu swarm rename / disable / list-user`** subcommands. Users edit yaml directly. If usage data shows demand, v0.13.x can add convenience commands.
- **Anti-sycophancy lint on user prompt content.** Token-only lint = false safety per v0.13's earlier dream pass on Persona SDK; behavioral lint requires fixture infrastructure (v0.14+).

## Build sequence (3 stages)

### Stage 1 — Schema + LoadUserPresets + registry-merge + validate command

**Goal**: yaml schema, load function with parse-failure-tolerant best-effort, registry merge with hard-error on built-in shadowing, `jutsu swarm validate` cobra command.

**Files**:
- `schemas/swarm.schema.json` — JSON Schema for `swarm.yaml`. Documents every field per Decision #4. Compiled in `lint-skills.yml` schema-validation job.
- `cli/internal/swarm/user_presets.go` — `LoadUserPresets(projectRoot string) (map[string]*Preset, []error, error)`. Returns: parsed presets, per-preset validation warnings (non-fatal), fatal yaml-load error (network of yaml.Unmarshal failures, NOT validation errors).
- `cli/internal/swarm/registry.go` — extends `Find` + adds `RegisterUserPresets(map[string]*Preset) []error`. Hard error when a user-preset name collides with a built-in. Returns the slice of collision errors so the caller can surface them on stderr without aborting other valid user presets.
- `cli/internal/cli/swarm_validate.go` — `jutsu swarm validate [path]` subcommand. Runs schema validation + name-collision check; reports findings without dispatching anything.

**Public API shape**:

```go
// cli/internal/swarm/user_presets.go
package swarm

// UserPresetSource indicates where a user preset came from.
type UserPresetSource string
const (
    SourceProject UserPresetSource = "user:project" // .kaijutsu/swarm.yaml
    SourceHome    UserPresetSource = "user:home"    // ~/.kaijutsu/swarm.yaml
)

// UserPreset wraps a built-in Preset value with its provenance.
// Stored in the registry the same way built-ins are; the Source
// field is consumed only by help-text rendering (Decision #8).
type UserPreset struct {
    Preset                       // embedded; UserPreset IS-A Preset
    Source UserPresetSource
}

// LoadUserPresets reads project + home swarm.yaml files, validates
// each entry against the schema, and returns the merged map.
// Project entries shadow home entries with the same name.
//
// Returns:
//   presets: map[name]*UserPreset of validated presets
//   warnings: per-preset issues (invalid InputKind, missing %s slots,
//             empty fields, intra-file duplicate names) — entry
//             SKIPPED but other entries in the SAME file are not
//             affected EXCEPT for intra-file duplicate-name errors
//             which reject the WHOLE file per Decision #6.
//   err: fatal yaml-parse-level errors only (file unreadable, malformed
//        YAML; not validation errors)
func LoadUserPresets(projectRoot string) (map[string]*UserPreset, []error, error)

// RegisterUserPresets adds the given user presets to the default
// registry. Hard-errors on built-in name collision per Decision #2;
// collision errors are returned but valid entries still register
// so the caller can surface partial-failure state.
//
// Type matches LoadUserPresets's return: map[string]*UserPreset.
// Internally, *UserPreset.Preset is what registers; Source metadata
// is preserved on a parallel registry map for help-text lookup.
func (r *PresetRegistry) RegisterUserPresets(m map[string]*UserPreset) []error
```

**Success criteria**:
- `schemas/swarm.schema.json` exists + is valid JSON Schema (compiled in `lint-skills.yml::validate-schemas`).
- `LoadUserPresets` returns project entries shadowing home entries on collision.
- `LoadUserPresets` skips invalid entries with warnings; valid entries in the same yaml still load.
- `RegisterUserPresets` hard-errors on built-in name collision; does NOT register the colliding preset; returns the error so the caller can surface it.
- `jutsu swarm validate` flags collisions, missing required fields, invalid InputKind, missing %s slots in DefaultPrompt + Synthesizer.
- All existing tests stay green.

**Tests**:
- `swarm/user_presets_test.go`: load/parse/validate/skip-invalid/project-shadows-home, malformed-yaml-doesn't-break-loading.
- `swarm/registry_test.go`: built-in-shadow-rejected, valid-user-preset-registered, find-returns-built-in-or-user.
- `cli/swarm_validate_test.go`: validate exits zero on clean yaml, non-zero with field-citation on broken yaml.

### Stage 2 — Cobra dynamic registration + per-InputKind flag wiring

**Goal**: At root cmd construction, load both yamls + register each user preset as a `jutsu swarm <name>` subcommand. Per-InputKind flag wiring reuses existing patterns from built-in subcommands.

**Files**:
- `cli/internal/cli/swarm.go::newSwarmCmd()` — after the existing AddCommand calls, call a new `addUserPresetSubcommands(cmd)` that loads via `swarm.LoadUserPresets(projectRoot)` + iterates the result map, registering one subcommand per user preset.
- `cli/internal/cli/swarm_user.go` — new file. `addUserPresetSubcommands` + `newUserPresetSubcommand(name string, p *swarm.UserPreset) *cobra.Command`. The latter selects the correct flag-binding helper based on `p.InputKind`:
  - `InputDiff` → reuses `--pr` / `--diff-from-branch` like pr-review
  - `InputFiles` → positional paths like doc-review
  - `InputPrompt` → positional prompt like brainstorm
- `cli/internal/cli/swarm.go::newSwarmCmd()::Long` — Help text mentions user presets show with `[user:project]` / `[user:home]` tags.
- Help-text formatting: extend the cobra subcommand's `Short` field at registration time to suffix `[user:<source>]` so `jutsu swarm --help` differentiates by source.

**Success criteria**:
- `.kaijutsu/swarm.yaml` with one user preset named `concise-review` → `jutsu swarm concise-review` is a usable subcommand.
- `jutsu swarm --help` lists `concise-review` with `[user:project]` tag in the Short column.
- `~/.kaijutsu/swarm.yaml` with `my-quick-audit` → also surfaces with `[user:home]` tag.
- Project preset `concise-review` shadows a home `concise-review` (only project version registers).
- Yaml parse error in either file → stderr warning + ALL built-in subcommands still work.
- Unknown persona name in user preset → cobra error at command time naming valid personas (per v0.10.1 enum sweep).
- Existing built-in subcommands unchanged.

**Tests**:
- `cli/swarm_user_test.go`: dynamic registration adds subcommand, help shows source tag, broken yaml doesn't break root cmd.
- Behavioral test runs `jutsu swarm <user-preset> --estimate` against a stubbed registry to verify per-InputKind flag wiring works for all 3 InputKinds.

### Stage 3 — Reference examples + housekeeping + final pr-review

**Goal**: 3 reference `swarm.yaml` files in `docs/examples/swarm/`, marker bump, CHANGELOG/ROADMAP/README, final swarm pr-review pass.

**Files**:
- `docs/examples/swarm/concise-pr-review.yaml` — composes pr-review's shape with a shorter synthesizer + 2 personas. Demonstrates `confidenceFloor` tuning + `mode: quick`.
- `docs/examples/swarm/deep-test-gap.yaml` — extends test-gap with `mode: full` + 4 personas (paranoid-security-claude, claim-auditor-claude, performance-deepseek, perf-purist-codex). Shows the cost trade-off (more dispatch = more diversity, but real money).
- `docs/examples/swarm/legacy-audit.yaml` — single user preset that takes positional file paths (InputFiles, like doc-review) and runs a custom synthesizer prompt blending code-archaeology's "WHY does this look this way" theory framing with security-audit's "what could break" lens. Single-preset composition; demonstrates how a user can borrow synthesizer-prompt language from two built-ins without auxiliary input plumbing (Decision #3 keeps the input shape standard). Run with: `jutsu swarm legacy-audit cli/internal/swarm/preset.go cli/internal/swarm/registry.go`.
- Each example has a leading comment block: copy this to `.kaijutsu/swarm.yaml`, edit, run `jutsu swarm validate`, then `jutsu swarm <name>`.
- `cli/internal/cli/init_agents_fragment.go` — marker `0.12.0` → `0.13.0`.
- `init_agents_fragment_test.go` — assertion update.
- `CHANGELOG.md` `[0.13.0]` entry: 3 stages summarized + dream-survival framing for the v0.13 ordering reversal.
- `ROADMAP.md` — flip Preset SDK row [ ] → [x]; v0.13.x persona-browse row added; v0.14+ Persona SDK gating-condition row remains.
- `README.md` v0.13 section: how to write swarm.yaml + pointer to the 3 examples + when to use yaml vs built-in.

**Final swarm pr-review** (after Stage 3 commits, before merge): `jutsu swarm pr-review --diff-from-branch main --strict --max-cost 5.0 --yes` against `main..HEAD`. Apply load-bearing findings; defensible-skip the rest.

**Success criteria**:
- `jutsu init` writes AGENTS.md fragment with `version=0.13.0`.
- 3 example yaml files validate against `schemas/swarm.schema.json`.
- All existing tests stay green.
- Cumulative `main..HEAD` diff passes the final pr-review (or fixes applied).

## Risks + mitigations

| Risk | Mitigation |
|---|---|
| User yaml parse error breaks ALL swarm commands | Decision #6 — load is best-effort; parse failure → stderr warning + skip user presets, fall back to built-ins. Built-in subcommands NEVER affected by user-yaml issues. Tested via `cli/swarm_user_test.go::TestUserYamlBrokenDoesNotBreakRoot`. |
| User preset's prompt has `%s` count mismatch (will fmt.Sprintf-error at dispatch) | Stage 1 schema validation requires DefaultPrompt + Synthesizer to have exactly the right number of `%s` slots. `jutsu swarm validate` surfaces this before the user runs the preset for real. |
| User preset's persona references a name not in agents.yaml | Existing v0.10.1 enum-rejection error at command time names valid personas. No new error path needed. |
| Help-text bloat when user has many presets | Acceptable for v0.13. v0.13.x can add `jutsu swarm list --user` filtered listing if usage data shows the bloat is real. |
| Built-in shadowing hard-error feels too strict | Defensible: built-in names are the contract; silent override would let user-yaml drift from public docs. Users can always pick `<original-name>-mine` or any unique suffix. |
| Dream "ghost town" warning — built-ins cover 90%, SDK sees ~zero adoption | v0.13.x will track usage via `findings.db`'s preset-name column. Dashboard query: count of `(preset_name, source=user:*)` rows over 90 days post-release. If <5% of recorded runs come from user presets, demote Persona SDK ambitions to v0.20+ and refocus on built-in preset depth. |
| RLHF convergence erodes cross-model dispatch value (the deeper dream concern) | Tracked separately as a v0.12.x A/B benchmark commitment (single-agent vs 3-agent shared-prompt on test-gap fixtures). v0.13 doesn't depend on resolving this; it ships the routing surface either way. |
| Persona references break when user upgrades agents.yaml | Same failure mode as today — agents.yaml personas are always referenced by name. v0.13 adds no new break surface. |
| Cobra subcommand registration at root construction time fails for some user yaml | If `addUserPresetSubcommands` panics or errors, root cmd construction wraps it in a recover/best-effort path; built-in subcommands always register successfully. Stage 2 test pins this. |

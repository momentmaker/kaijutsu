# v0.11.0 — autopilot v2 + swarm.RunPipeline extraction

**Status**: draft
**Date**: 2026-05-07
**Type**: minor (replaces v0.10 Stage 2 stubs with real implementations + new core skill `autopilot`)

---

## Why

Two converging needs:

1. **Carryover from v0.10.1 deferral.** v0.10's `eval preset` + `eval swarm-skill` ship as loud-warned stubs (`presetModeResolver` returns claude regardless of `<preset>:<mode>` pair). Real integration was scoped to v0.10.x via `swarm.runSwarmPipeline` extraction. v0.10.1 measured the function at 470 LOC of cobra-coupled logic — too large for a polish patch. v0.11.0 is the right home: minor bump, fresh branch, room for the heavy lift.

2. **Autopilot v2.** Existing `~/.claude/skills/autopilot/SKILL.md` (362 lines) is a solid intent-to-PR pipeline but reaches outside the kaijutsu surface — single code-reviewer agent, no anti-sycophancy at the design phase, no spec-vs-impl drift detection, no skill-aware orchestration. Result: the pipeline yes-ands the user's first instinct. v2 makes adversarial pressure the spine: multi-agent review at every artifact gate, dream-driven brainstorm with anti-sycophancy enabled, configurable cost cap with hard ceiling, reverse-drift detection at ship time.

The `swarm.RunPipeline` extraction is **load-bearing for autopilot v2** — autopilot needs a non-cobra entry point to dispatch swarm passes. Bundling them in the same release is therefore not feature creep; the extraction is on the autopilot critical path.

A `jutsu swarm dream --mode full` pass on the v2 design (54 findings, archived to `~/.kaijutsu/dreams/`) surfaced 5 load-bearing concerns that re-shaped the proposal:

- Cascading errors with no firewall under one-gate model → **kept 2-gate default** (brainstorm + PR-on-GitHub).
- Multi-agent consensus is a correlation filter, not a correctness oracle → **never auto-apply doc-review findings; always report-only**.
- $5/run cost cap is fiction at realistic feature complexity → **soft cap raised to $20 default, $100 hard ceiling in skill code, env-var override above ceiling**.
- Reviewer/generator boundary violation if findings auto-mutate artifacts → **report-only, user-driven application**.
- Prompt-injection blast radius compounds across 4-stage pipeline → **hard cost ceiling lives in skill code**, not in-repo `.kaijutsu/autopilot.yaml`. Ceiling can still be raised by a malicious PR to the skill itself, but at a different threat-surface than yaml: skill changes flow through release tagging + sigstore signing for `skills/core/`. Verify-by-cosign at install time means a tampered `skills/core/autopilot/SKILL.md` fails the install gate. yaml is unsigned + writable per-project. Different attack-surface → different defense.

## Locked decisions

| # | Decision | Choice |
|---|---|---|
| 1 | Gate model | **2 gates** by default (brainstorm + PR-on-GitHub). `post_spec` and `post_plan` opt-in for paranoid users via `.kaijutsu/autopilot.yaml`. |
| 2 | Findings auto-apply | **Always report-only**. Findings surface inline; user decides which to apply. Reviewer/generator boundary preserved. |
| 3 | Cost cap | **Layered**: soft cap = config default $20 + warn-pause-at-50%; hard ceiling = $100 in skill code; CLI flag `--max-cost N` overrides soft within ceiling; env var `KAIJUTSU_AUTOPILOT_HARD_CAP_OVERRIDE=N` raises ceiling per-shell (not in repo). |
| 4 | Skill-aware orchestration | **Defer to v0.12+**. `jutsu suggest "<phase intent>"` integration adds complexity beyond v0.11 core. Document as roadmap item. |
| 5 | Persona pack additions | **3 new built-ins**: `claim-auditor-claude`, `cross-file-gemini`, `perf-purist-codex`. Pure additions to `BuiltinPersonas()`; lift non-autopilot users too. |
| 6 | `.kaijutsu/autopilot.yaml` | **Optional**. Zero-config works using built-in defaults + sensible persona pack. Power users override. |
| 7 | Old autopilot at `~/.claude/skills/autopilot/SKILL.md` | **Replace**, with one-time stderr note: "autopilot v2 supersedes the v1 skill — v1 preserved at `~/.claude/skills/autopilot/.archived/SKILL.md` for rollback". |
| 8 | Stage 2 stub replacement | **Real `swarm.RunPipeline` integration** for `eval preset` + `eval swarm-skill`. Stub stderr warning removed. Behavior parity for `jutsu swarm pr-review` (and all other preset entry points) verified by passing existing test suite. |
| 9 | Reverse-drift gate | **Informational PR tag**. After Phase 5 final pr-review, autopilot calls `swarm.RunPipeline` (not the cobra wrapper) with the `reverse` preset against `--spec <approved-spec-path-from-state-file> --diff origin/main...HEAD`. Drift summary written to PR description; PR tagged `autopilot-drift` if findings present. **Not blocking** — user reviews drift on GitHub. Different lens than pr-review (drift = spec↔impl divergence; pr-review = bug catching), so the duplicated cost is intentional. |
| 10 | Marker version | `0.10.1` → `0.11.0` in `init_agents_fragment`. |
| 11 | CLI surface | New `jutsu autopilot` subcommand group at `cli/internal/cli/autopilot.go`: `init` (write `.kaijutsu/autopilot.yaml` from defaults; refuses to overwrite without `--force`), `status` (read state file), `abort` (clean state + worktree), `resume` (continue from last completed phase per state file), `run "<intent>"` (non-interactive: skips Gate 1 if `--yes`, else exits with "use /autopilot inside an agent CLI for interactive runs"). The `/autopilot` slash command remains the primary interactive entry point. |

## Build sequence (3 stages)

### Stage 1 — `swarm.RunPipeline` extraction + stub replacement

**Goal**: Extract the cobra-coupled `runSwarmPipeline` (470 LOC at `cli/internal/cli/swarm.go:549`) into a non-cobra public API at `cli/internal/swarm/pipeline.go`. `eval preset` + `eval swarm-skill` route through real `swarm.RunPipeline` per side. Stub stderr warning removed. All v0.6/v0.7/v0.8/v0.9/v0.10 swarm behavior preserved.

**Public API shape**:

```go
// cli/internal/swarm/pipeline.go
package swarm

func RunPipeline(ctx context.Context, opts PipelineOpts) (*Result, error)

type PipelineOpts struct {
    ProjectRoot    string
    Preset         *Preset
    Input          *InputContext
    PerAgentBudget float64
    Timeout        time.Duration
    Strict         bool
    Personas       []string
    SynthAgent     AgentName
    Mode           string         // quick | full
    MaxCostUSD     float64
    StderrW        io.Writer
    Replay         string
    PostComment    bool
    Format         string         // markdown | json
    DreamLenses    []string
    ConsentConfig  *Config
    // … additional fields as the cobra wrapper currently uses
}

type Result struct {
    Synthesis    *Synthesis
    AgentResults []AgentResult
    RunID        string
    SHA          string
    EstimatedCost float64
    ActualCost   float64
}
```

`cli/internal/cli/swarm.go::runSwarmPipeline` becomes a thin cobra → `PipelineOpts` adapter. `presetModeResolver.Resolve` (`eval preset` shape) calls `swarm.RunPipeline` per side. Same for `eval swarm-skill` (with-skill side loads the SKILL.md; without-skill side does not).

**Success criteria** (specific, testable):
- All existing swarm tests green (no v0.6+ behavior regression).
- `swarm/pipeline_test.go` exercises `RunPipeline` end-to-end via stub agents (covers the 8 behaviors pinned in the Risk table above).
- `eval preset` per-side artifacts have **semantic divergence** (synthesis findings_count differs between sides AND from the v0.10 stub case which returned identical claude output regardless of preset:mode pair). Byte-equality is intentionally NOT the assertion (timestamps + run IDs always differ).
- `eval swarm-skill` similarly has semantic divergence between with-skill and without-skill sides.
- Grep for "Stage 2 stub warning" stderr in `eval_swarm_shape.go` returns nothing.
- Test invokes the public `swarm.RunPipeline` API, not the cobra wrapper, to validate Stage 1's architectural intent (doc-review #6).

**Risk**: extraction has to preserve every existing v0.6+ behavior. Concretely:

| Behavior | Source | Pin via |

Heavy unit-test pass before refactor. Integration test runs the existing `jutsu swarm pr-review` end-to-end pre + post extraction; diffs synthesis output.

### Stage 2 — Autopilot v2 skill core

**Goal**: Replace `~/.claude/skills/autopilot/SKILL.md` (362 lines, single-reviewer + 2 gates) with v2 (multi-agent review at every artifact gate, configurable, cost-capped). Also ship as `skills/core/autopilot/` for distribution via `jutsu install autopilot`.

**Performance / efficiency notes** (from doc-review):
- Persona resolution is cached once at autopilot start (not re-resolved per phase).
- `KAIJUTSU_AUTOPILOT_HARD_CAP_OVERRIDE` env var is read once at autopilot start, not per agent call.
- State file writes are batched on phase transitions (not on every polish pass).
- The reverse-drift gate runs an additional swarm pass; cost is intentional because the `reverse` preset uses a different lens (spec↔impl divergence) than `pr-review` (bug catching). Document this in `references/cost-model.md`.

**`findings.db`**: the SQLite database introduced in v0.7 at `~/.kaijutsu/findings.db`. Schema documented in `cli/internal/findings/schema.go`. Autopilot's LEARN phase writes one row per finding from the run; existing v0.7 indexes (run_id, position, lens) cover the read path.

**Skill structure**:

```
skills/core/autopilot/
  skill.yaml                          # name, version, deps, layout: rich
  SKILL.md                            # core protocol + phase descriptions
  references/
    config-schema.md                  # .kaijutsu/autopilot.yaml reference
    cost-model.md                     # soft cap + hard ceiling + env override + reverse-drift cost note
    persona-defaults.md               # which personas run at which phase
  runbooks/
    abort-and-resume.md               # state file format + resume protocol
    drift-detection.md                # reverse-drift gate behavior
```

(No `scripts/` subdir for v0.11.0. Cost estimation + state-file writes happen in skill body via the agent's existing tooling. If a need for shell-script helpers surfaces during implementation, add in v0.11.x with explicit author + invocation contracts.)

**Skill flow** (matches dream-revised proposal):

```
/autopilot {intent}
  → Phase 1: BRAINSTORM (interactive — anti-sycophancy via jutsu swarm dream)
  → ★ GATE 1 (configurable: skip | review) ★
  → Phase 2: SPEC
      → write spec to docs/specs/<date>-<slug>.md
      → swarm doc-review on spec [report-only — findings printed to stderr]
      → record approved-spec path in state file (key: approved_spec_path)
  → Phase 3: PLAN
      → swarm doc-review on plan [report-only]
  → Phase 4: BUILD (stage 1..N — each followed by polish loop)
  → Phase 5: SHIP
      → final swarm pr-review (full lens)
      → reverse-drift gate: swarm.RunPipeline with reverse preset
        + --spec <state.approved_spec_path> + --diff origin/main...HEAD
        → drift findings appended to PR description as <details> block
        → PR labeled `autopilot-drift` if findings present
      → gh pr create (or autopilot test mode: write planned PR JSON to .kaijutsu/autopilot-pr.json + skip gh)
  → ★ GATE 2 = PR review on GitHub (PR semantics; always exists) ★
  → Phase 6: LEARN
      → write run summary to ~/.claude/projects/<project>/memory/autopilot-run-<date>-<slug>.md
      → record findings into ~/.kaijutsu/findings.db (existing v0.7 schema)
      → update MEMORY.md if lesson is broadly applicable
```

**State file** at `.kaijutsu/autopilot-state.md` (project-scoped, kaijutsu-namespaced; replaces existing v1's `.claude/autopilot-state.md`):

```yaml
---
intent: "<original intent>"
phase: brainstorm | spec | plan | build | ship | learn | done
slug: <feature-slug>
approved_spec_path: docs/specs/<date>-<slug>.md   # set after Gate 1; consumed by reverse-drift
plan_path: docs/specs/<date>-<slug>-plan.md       # optional, autopilot may bundle plan into spec
branch: feat/<slug>
pr: <url-or-empty>
started_at: <ISO timestamp>
gate_responses: { brainstorm: approve | revise | reject }
cost_so_far_usd: <running total>
---
```

**Findings application path** (consumes Decision #2 = report-only):
- After `swarm doc-review` on spec/plan, findings are printed to stderr inline + appended to a `findings.md` artifact in the iteration directory.
- Autopilot does NOT mutate the spec/plan automatically.
- User reviews findings; if they want changes applied, they re-run autopilot (`/autopilot resume`) after editing the spec themselves OR they ask the agent CLI directly to apply specific findings.
- This preserves the reviewer/generator boundary that dream finding #4 / #10 surfaced.

**Test-mode hook** (consumes doc-review finding #1: PR creation not automatable in CI):
- Env var `KAIJUTSU_AUTOPILOT_TEST_MODE=1` skips `gh pr create`.
- Instead, autopilot writes a `.kaijutsu/autopilot-pr.json` file with the PR title, body, branch, and labels that WOULD have been submitted.
- CI tests assert against this JSON file, not against a real GitHub API call.
- Production runs are unaffected.

**Default config** (zero-config, ships as built-ins; users override via `.kaijutsu/autopilot.yaml`):

```yaml
gates:
  brainstorm: review        # skip | review (default review = pause for user approval)
  post_spec: skip           # skip | review — off by default; paranoid users enable
  post_plan: skip           # skip | review
  pr: github                # PR review IS gate 2 — always; not config-overridable

brainstorm:
  preset: dream
  personas: [brainstorm-creative-claude, architecture-purist-gemini, claim-auditor-claude]
  mode: full
  lenses: all                # 8-lens canonical cycle

spec_review:
  preset: doc-review
  personas: [architecture-purist-gemini, paranoid-security-claude, claim-auditor-claude]
  mode: quick

plan_review:
  preset: doc-review
  personas: [perf-purist-codex, claim-auditor-claude, cross-file-gemini]
  mode: quick

per_stage_polish:
  max_passes: 4              # current /polish cap

final_review:
  preset: pr-review
  personas: [paranoid-security-claude, architecture-purist-gemini, perf-purist-codex, claim-auditor-claude]
  mode: full
  strict: true               # lie-to-them filter

findings:
  auto_apply: false          # report-only; never mutate artifact silently
  escalate_threshold: blocker  # blocker findings pause for user

cost:
  max_total_usd: 20.00       # soft cap (config-overridable)
  pause_at_pct: 50           # mid-flight budget pause + confirm
  # hard ceiling = $100 in skill code; env var raises per-shell

orchestration:
  skill_suggest: false       # defer to v0.12+
  drift_check: tag           # tag | block | off
```

**Cost cap enforcement** (matches Decision #3):

```
1. soft cap (yaml or default $20)
   → autopilot tracks running cost
   → at pause_at_pct (50%), pause + confirm-continue prompt
   → at soft cap, pause + require explicit --raise-cap N
2. hard ceiling = $100 (constant in skill code)
   → CLI flag --max-cost N can raise soft cap up to ceiling
   → above ceiling, error: "set KAIJUTSU_AUTOPILOT_HARD_CAP_OVERRIDE in shell to proceed"
3. env override raises ceiling per-shell only
   → not stored in repo, not in yaml
   → defense against malicious PR setting yaml max_cost: 10000
```

**Success criteria** (specific, testable):
- `/autopilot {intent}` runs end-to-end on a test repo, opens a real PR, exits clean.
- `/autopilot resume` picks up from last completed phase (state file).
- `/autopilot abort` cleans up worktree + branch + state file.
- `/autopilot status` reports current phase from state file.
- Hard ceiling test: malicious yaml `max_cost: 10000` does NOT override the $100 ceiling.
- Cost mid-flight test: soft cap of $5 with simulated burn rate triggers pause-at-50% + confirm.
- Findings test: doc-review finding never mutates the spec/plan artifact; only the user-driven application path can.
- Reverse-drift test: spec drift between approved spec and the pre-PR branch diff (`origin/main...HEAD`) results in PR description drift block + `autopilot-drift` label on the PR.
- Old autopilot test: `~/.claude/skills/autopilot/.archived/SKILL.md` exists post-replacement; original v1 content preserved.

## Risks + mitigations

| Risk | Mitigation |
|---|---|
| `runSwarmPipeline` extraction regresses pre-existing v0.6+ swarm behavior | Heavy test pass before refactor; pre/post integration test runs `jutsu swarm pr-review` end-to-end and diffs output |
| Autopilot loop hits unbounded retry → blows past hard ceiling silently | Hard ceiling lives in skill code, not config. Env var override is per-shell, not in repo. |
| Multi-agent consensus on a wrong call (groupthink — dream finding #2/#8) | Mitigations: include at least 1 HTTP-backed persona for training-corpus diversity (deepseek option in plan_review); ship the lens-blind-spot warning behavior we already use in dream synthesis ("all-agents-agreed warning" surfaces convergence as potential bias) |
| Prompt injection via /autopilot {intent} or dependency comment compounds across 4 stages (dream finding #15/#20/#21) | Sanitize artifacts between stages (strip `<<<USER>>>` sentinels, control characters); hard cost ceiling at runner level prevents runaway injection-driven retry loops |
| Reverse-drift detection produces false-positive drift signals on legitimate refactors | Drift gate is INFORMATIONAL (PR tag), not blocking. User reviews on GitHub; false positives are noise, not blockers |
| Old `~/.claude/skills/autopilot/SKILL.md` users hit silent behavior change post-replace | One-time stderr note on first invocation; v1 preserved at `.archived/SKILL.md` for rollback; CHANGELOG breaking-change section calls it out |
| Autopilot run cost exceeds user expectation despite $20 default | Pre-flight `--estimate` projection at gate 1; mid-flight pause-at-50%; visible cost tracking in stderr; soft cap default low enough that surprise stays small |
| Stage 1 extraction balloons past plan budget (v0.10.1 lesson — measured 470 LOC) | If extraction proves harder than planned, ship Stages 2+3 as v0.11.0 and stage 1 as v0.11.1; signal early if scope drifts |

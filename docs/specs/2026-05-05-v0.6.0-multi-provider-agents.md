# v0.6.0 — Multi-Provider Agents (HTTP Driver + agents.yaml)

**Status:** draft, pending `jutsu swarm doc-review`
**Author:** rubberduck
**Date:** 2026-05-05
**Targets release:** v0.6.0
**Touches:** new package `cli/internal/agents/`, refactor `cli/internal/swarm/agent.go`, new `jutsu agent` subcommand group, new `~/.kaijutsu/agents.yaml` + `<repo>/.kaijutsu/agents.yaml`, new JSON Schema.

---

## Problem

**Problem:** `jutsu swarm` only works with three hard-coded native CLIs (claude/codex/gemini). Users who want to include other capable models in the swarm — DeepSeek, GLM, Qwen, Kimi, local Ollama — have no clean path. The CLI-as-harness workaround (`ANTHROPIC_BASE_URL=...`) leaks metadata to Anthropic via Claude Code telemetry endpoints that don't respect the override, and locks users into one harness's prompt-engineering quirks.

**Who feels it:** swarm power-users who want diverse model perspectives, cost-sensitive teams that prefer cheaper providers for early-pass review, and security-conscious users who don't want a third-party CLI involved when they have a direct API endpoint.

**When:** every `jutsu swarm <preset>` invocation today implicitly assumes "you have all three CLIs installed and authed." Half-installed setups already fail; non-Big-Three providers can't even be tried.

**Today's workaround:** export `ANTHROPIC_BASE_URL` + `ANTHROPIC_API_KEY` pointing at DeepSeek and re-run `jutsu swarm` — but Claude CLI still calls Anthropic for telemetry/error reporting/Statsig, and the user gets Claude CLI's tool-use behavior (which underperforms with smaller models per the May 2026 LiveCodeBench HN thread).

**Cost of doing nothing:** swarm's value compounds with model diversity. Three models from one vendor (Anthropic only) is a weaker signal than three models from three vendors. Users will route around jutsu rather than wait.

## In scope

### Core driver abstraction
- New `AgentDriver` interface in `cli/internal/agents/` formalizing what a swarm participant is.
- **Four** concrete drivers: `cli` (current behavior), `http` (direct OpenAI-compat / Anthropic-compat HTTP), `cli-compat` (wraps a native CLI with `BASE_URL`+`KEY` override + telemetry-disable env), `mcp` (MCP server as swarm peer — see "MCP-as-peer" below).
- Two-layer YAML config: `~/.kaijutsu/agents.yaml` (provider + persona catalog) + `<repo>/.kaijutsu/agents.yaml` (enabled list + project overrides).
- Resolution order: project enabled list ∩ (project overrides ⊕ global catalog).
- Environment-variable indirection for API keys (`api_key_env: DEEPSEEK_API_KEY`). Keys never live in YAML.
- `jutsu agent` subcommand group: `list`, `add`, `enable`, `disable`, `test`, `doctor`, `remove`.
- JSON Schema (`schemas/agents.schema.json`) wired into `jutsu lint`.
- Vendored "known-good" provider catalog in `cli/internal/agents/catalog.go` (deepseek, glm, kimi, ollama-local — opt-in via `jutsu agent add deepseek`, not auto-enabled).
- HTTP driver supports OpenAI-compat (`/v1/chat/completions`) and Anthropic-compat (`/v1/messages`) protocols.
- Per-driver cost reporting (HTTP reads `usage` block from response; CLI reads stderr cost line as today).
- Backward compatibility: with no `agents.yaml` present, swarm behavior is byte-identical to v0.5.0.
- Telemetry-leak warning fires at **runtime** on the first invocation of any `cli-compat` driver per swarm run (not at `agent add` time — install-time warnings are easily ignored and forgotten). Once-per-run, suppressible with `--no-telemetry-warning`.

### Personas — registry-installable agent flavors
- **Persona = (provider, model_override?, system_prompt, tags) tuple.** A persona is what gets dispatched to a swarm slot, not a raw provider.
- `personas:` top-level section in `agents.yaml`. Each persona references a provider by name and supplies a system prompt + optional model override + tags.
- Built-in personas shipped with the CLI: `default-claude` / `default-codex` / `default-gemini` (current v0.5 behavior — what the user gets out of the box). Plus 4 reference flavored personas to show the pattern: `paranoid-security-claude`, `pragmatic-codex`, `architecture-purist-gemini`, `brainstorm-creative-claude`. **7 total built-in personas.**
- Skills can declare `requires_persona_tags: [security]` in `skill.yaml`. Loader hard-fails if no enabled persona has the tag.
- `jutsu swarm pr-review --personas paranoid-security-claude,pragmatic-codex,default-gemini` dispatches the named personas instead of provider-default personas.
- **Personas are skill-shaped**: future `jutsu install persona:senior-staff-engineer` (deferred to v0.7 when the registry layer for non-skill artifacts is built; v0.6 only supports user-declared personas in YAML).

### Prompt-cache awareness (HTTP driver)
- HTTP driver shapes outgoing prompts to maximize provider-side prompt caching:
  - **Anthropic API**: uses `cache_control: {type: "ephemeral"}` on the stable system + skill-prompt prefix; variable suffix (the actual diff/files) lands outside the cache mark.
  - **OpenAI-compat**: prepends a stable prefix that hits OpenAI's automatic prompt caching threshold (≥1024 tokens); we pad if needed with the canonical skill description text.
- Cache hit/miss reported in `Result.CacheStatus` (`hit | miss | partial | unsupported | skipped-too-short`).
- Cost-tracking accounts for cached-input pricing (~10% of normal input cost on Anthropic).
- Falls back gracefully when the provider doesn't support caching.

### `jutsu swarm --estimate` (dry-run cost preview)
- Before any agent invocation: tokenize the assembled prompt (provider-specific tokenizer where available; tiktoken-go fallback), multiply by per-provider rate cards, sum.
- Output table: per-provider {input_tokens, output_estimate, $cost_estimate}, with a TOTAL line.
- Honors `--max-cost` at the **aggregate** level only (per-provider caps remain a non-goal): `--estimate` warns when sum-of-projections exceeds budget. No per-provider warning.
- Per-provider rate card lives in `agents.yaml` under `cost:` block; vendored defaults populate at `agent add` time, manually editable.
- `jutsu swarm <preset> --estimate` exits 0 without invoking agents. Pure dry-run.

### MCP-as-peer driver (4th driver kind)
- `driver: mcp` provider kind. References a configured MCP server (stdio or HTTP) that exposes a single agreed-upon tool: `analyze(args: {preset, severity_vocab, input}) → JSON findings array`. Full signature in **D7**.
- **Use case:** static analyzers (semgrep, eslint, ripgrep-based fingerprint-matchers) participate in the swarm as deterministic peers. When semgrep + claude + codex independently flag the same line, that's near-certain real signal — high-precision finding.
- Vendored MCP-driver examples in `cli/internal/agents/mcp_examples.md`: how to wire `semgrep-mcp`, `eslint-mcp`, custom in-house analyzers.
- Cost: MCP drivers report `CostUSD: 0` (deterministic local execution).
- The synthesizer treats MCP findings as peer findings in the disagreement table (same scoring rules for cross-reviewer convergence) **with one asymmetry**: MCP-driver findings at `info` severity are dropped before synthesis (deterministic-tool noise floor). MCP findings at `minor` and above appear in the disagreement table and synthesis just like LLM findings, tagged `[deterministic]`. Divergence between MCP and LLMs at issue/blocker level is high-signal.
- v0.6 ships **the `mcp` driver itself as a required, fully-tested core feature** (parses config, dispatches to MCP servers, surfaces errors, populates Result). The **reference semgrep-mcp integration is documentation-only** — `cli/internal/agents/mcp_examples.md` ships with a working YAML config block plus prose; whether the upstream `semgrep-mcp` package exists is irrelevant to v0.6 release readiness. The driver is required; any specific reference integration is illustrative.

## Non-goals

- **Streaming output.** All drivers buffer full response then return. Streaming is a v0.7+ concern.
- **Multi-model routing per skill.** Swarm preset declares logical agent slots (e.g. `[claude, codex, gemini]` today, or `[claude, deepseek, gemini]` after v0.6); we don't pick provider-by-skill yet.
- **Cost budgets per provider.** `--max-cost` remains aggregate across the swarm. Per-provider caps deferred.
- **Custom protocol shims.** OpenAI-compat + Anthropic-compat only. No Cohere, no Vertex-native, no Bedrock-native. Users with those APIs use a sidecar gateway (litellm, openrouter).
- **TUI / chat mode.** This is not aivo. We are not building a multi-provider chat UI.
- **Pluggable third-party drivers.** v0.6 ships exactly the four drivers listed (cli/http/cli-compat/mcp). Third-party drivers (loadable plugin / external sidecar) deferred to v0.7+.
- **Persona registry / `jutsu install persona:foo`.** v0.6 supports user-declared personas in YAML only. Registry-shaped persona installation is v0.7 (needs registry-side schema work for non-skill artifacts).
- **Streaming partial findings to TUI.** Live partial-finding streaming is v0.7.
- **Local-model noise gate (Ollama 7B classifier).** Rejected on cost/benefit grounds — see ROADMAP. Replaced by deterministic rule-based skip + cheap-tier routing (planned for v0.7).
- **Quality fingerprinting + confidence-weighted synth.** Local SQLite that learns from user accept/dismiss is v0.7.
- **Multi-stage swarm pipelines.** `jutsu swarm pipeline <name>` chaining multiple presets is v0.7.
- **Reverse swarm (spec-vs-impl drift).** Comparing PR to its closing spec is v0.7.
- **Auto-detection of API keys** in the user's shell. `jutsu agent doctor` reports what's missing; doesn't probe for keys.
- **Per-provider rate-limit retry policy.** v0.6 surfaces HTTP 429 as `r.Err` and continues. Smart retry is v0.7.
- **Cross-provider load balancing.** One provider per agent slot per swarm run.
- **Anthropic-compat support for cli-compat driver beyond Claude Code.** Codex CLI's `OPENAI_BASE_URL`/`OPENAI_API_KEY` and Gemini CLI's `GEMINI_API_KEY` are supported; other native CLIs (cursor, aider, etc.) deferred.

### Prompt cache
- [ ] HTTP driver against Anthropic API marks system+skill-prompt prefix with `cache_control` ephemeral.
- [ ] HTTP driver against OpenAI-compat ensures stable prefix hits the ≥1024-token threshold (canonical skill description used as padding when natural prompt is shorter).
- [ ] `Result.CacheStatus` populated for HTTP driver runs (`hit | miss | partial | unsupported | skipped-too-short`).
- [ ] `Result.CostUSD` reflects cached-input pricing when applicable. **Partial-cache cost rule:** when `CacheStatus == "partial"` (some tokens hit cache, others didn't), cost is computed pro-rated: `cost = cached_tokens × cached_rate + uncached_tokens × normal_rate + output_tokens × output_rate`. Unit assertion: fixture call returning `usage: {input_tokens: 500, cache_read_input_tokens: 500, output_tokens: 100}` produces a cost matching the formula within 0.1% rounding tolerance.
- [ ] Unit assertion: when the HTTP driver's `Result.CacheStatus == "hit"`, `Result.CostUSD` is computed using the cached-input price (10% of normal Anthropic input rate; OpenAI-published cached rate) and the difference vs. uncached cost is verified by the test against a fixture response that includes `usage.cached_tokens`.
- [ ] Integration assertion via **mocked Anthropic endpoint** (`httptest.NewServer`): the test server responds to two consecutive `POST /v1/messages` calls — first with `usage: {input_tokens: 0, cache_creation_input_tokens: 1000, cache_read_input_tokens: 0}` (real Anthropic API field names — first call writes to cache), second with `usage: {input_tokens: 0, cache_creation_input_tokens: 0, cache_read_input_tokens: 1000}` (second call reads from cache). Driver's reported `Result.CostUSD` for call 2 is computed against cache-read pricing (10% of normal input rate per Anthropic's published rate card) and asserted to be ≥50% lower than call 1. Mocking sidesteps Anthropic's real 5-minute ephemeral TTL and CI flakiness.

### MCP-as-peer
- [ ] `driver: mcp` provider kind parses with the following fields:
  - `transport: stdio | http` — required enum.
  - For `stdio`: `command:` (string, required) + `args:` (array of strings, optional).
  - For `http`: `endpoint:` (URL string, required) + `headers:` (optional map; values are ENV-var names, not literal secrets — driver looks each value up via `os.Getenv()` at invoke time, identical pattern to `api_key_env`). E.g., `headers: {Authorization: SEMGREP_TOKEN_ENV}` resolves to `Authorization: $SEMGREP_TOKEN_ENV` at invoke. Literal-value headers (non-secret) use the `headers_literal:` block.
  - `tool_name:` (string, optional, defaults to `analyze`) — name of the MCP tool to invoke.
  - `timeout_seconds:` (int, optional, defaults to global `defaults.http.timeout_seconds` for http transport, 60s for stdio).
- [ ] MCP driver invokes the configured MCP server with the assembled prompt, expects a JSON findings array conforming to the preset's severity vocabulary.
- [ ] `Result.CostUSD` is `0.0` for MCP-driver runs.
- [ ] MCP driver findings appear in the disagreement table tagged with `[deterministic]` to distinguish from LLM findings.
- [ ] At least one reference MCP integration documented in `cli/internal/agents/mcp_examples.md` (semgrep-mcp config example, even if the upstream package is not yet shipped — config-only is acceptable for v0.6).
- [ ] MCP-driver invocation respects context cancellation; failed MCP calls surface as `Result.Err` like any other driver.
- [ ] **MCP out-of-vocab severity handling:** when an MCP-driver finding's severity isn't in the preset's severity vocabulary, the driver does NOT relabel — it surfaces the finding as `Result.Err: "MCP server '<name>' returned unknown severity '<sev>'; expected one of [...]"` and the entire response is discarded (not partially merged). Prevents a misconfigured MCP server from polluting findings with unintended severities. Trade-off: one bad finding kills the whole MCP response, but predictable failure beats silent relabeling.

## Decisions (resolved during spec authoring — no further sign-off needed)

- **D1 — HTTP protocol shape:** internal representation = OpenAI shape (`messages: [{role, content}]`), with system prompt as the first message. Protocol-specific drivers transform on egress: Anthropic egress moves system to top-level `system` field; OpenAI keeps as first message.
- **D2 — Vendored provider catalog:** bundled in v0.6 binary. Live `providers.json` deferred to v0.8+ once the catalog grows past ~10 entries.
- **D3 — `agents.yaml` written by default in `jutsu init`:** opt-out via `--no-agents-config`.
- **D4 — `agent test` probe order:** `GET /models` first (free for OpenAI-compat); fallback to 1-token completion when `/models` is unsupported or returns non-2xx.
- **D5 — `agents.yaml` schema versioning:** `version: 1` enforced from day one.
- **D6 — Persona vs provider namespacing:** providers and personas in separate maps. `--personas` accepts persona names only.
  - **Name resolution rules:**
    - If name X matches a persona → use it (highest priority).
    - If name X matches a provider but no persona → resolve to `default-<X>` (auto-synthesized if not declared); emit one-line stderr hint.
    - If name X matches **both** a persona and a provider (collision) → persona wins (persona namespace has priority); stderr warning notes the shadow.
    - User-declared persona named `default-<provider>` (e.g., user redefines `default-claude`) is permitted — it overrides the built-in. **This invalidates legacy v0.5 cache keys for any swarm using that persona** (because the system_prompt salt differs); spec'd as expected behavior, not a bug.
  - `--agents` (v0.5 legacy) accepts provider names directly and dispatches the corresponding `default-<provider>` persona. Unifying flags is a v0.7 cleanup.
  - **`--personas` + `--agents` together:** rejected at flag parse time with "use one or the other, not both" — they'd address the same dispatch slots and merging semantics aren't worth specifying for what is already a deprecated transition path.
- **D7 — MCP tool contract:** Tool name `analyze` standardized; `tool_name:` config override defaults to `"analyze"`. Tool signature:
  ```
  analyze(args: {
    preset: string,            // "pr-review" | "doc-review" | "brainstorm" | "refactor-plan" | "security-audit"
    severity_vocab: string[],  // e.g. ["blocker","issue","minor","info"]; MCP server uses this exact set
    input: string              // the assembled prompt body — diff/files/artifact, NOT including persona+skill system prompts
  }) → findings: Finding[]
  ```
  where `Finding = {severity: string, file?: string, line_range?: string, summary: string, reasoning?: string, confidence?: number}`. The MCP server gets the preset name and severity vocabulary explicitly so it can shape findings correctly without inferring from the prompt. The `input` is just the diff/files (the deterministic-tool's actual work product) — system prompts intended for LLMs are stripped before the MCP call.
- **D8 — Prompt-cache pad threshold (OpenAI providers):** three regions explicitly:
  - **`< 820 tokens`** (under 80% of OpenAI's 1024-token cache threshold): padding skipped, `CacheStatus: skipped-too-short`. Sending extra padding bytes here costs more than caching saves.
  - **`820 ≤ tokens < 1024`**: padding enabled — append canonical skill description as cache-friendly suffix until prompt reaches 1024 tokens; `CacheStatus: hit | miss` per provider response.
  - **`≥ 1024 tokens`**: no padding needed — prompt already eligible for caching naturally; `CacheStatus: hit | miss` per provider response.
  **Scope:** D8 applies to ALL `protocol: openai-compat` providers (OpenAI itself, DeepSeek, GLM, Kimi, etc.) — they all share the 1024-token automatic-cache threshold. Anthropic providers (`protocol: anthropic-compat`) ignore D8 entirely; they use `cache_control: ephemeral` markers regardless of prompt length. Token measurement uses the provider's native tokenizer when available, tiktoken-go otherwise.
- **D9 — Estimate accuracy claim:** ±20% for tiktoken-go fallback; ±5% for provider-native tokenizers. `--estimate` footer prints the disclaimer matching the actually-used tokenizer.

## Risks

- **Provider API drift** (DeepSeek/GLM change response shape): mitigation — per-provider integration test in CI; `jutsu agent test` exercises the path on first use; surface protocol mismatch as a clear error rather than a parse panic.
- **Key leakage via debug logs:** mitigation — single `agents.SanitizeForLog(string)` helper; mandatory use in any error-formatting path; unit tests assert no key appears in formatted output across all error branches.
- **Schema migration friction** when v0.7 adds fields: mitigation — `version: 1` enforced; loader emits clear migration message on version mismatch.
- **HTTP driver and CLI driver produce subtly different prompts** (e.g. CLI gets system prompt embedded vs HTTP sends it as `system` field), causing cache-key divergence: mitigation — cache key includes driver+persona identity *only when the mix differs from the v0.5 legacy set*; pure-default-cli runs reuse legacy keys for backward compat. Document that switching drivers or adding personas invalidates the legacy cache (intentional — prevents cross-driver false convergence). Implementation: `cacheKeyFor(input, mix)` returns the legacy v0.5 hash when `mix == legacyMix`, otherwise SHA256(input ‖ NUL ‖ canonicalized(mix)). **Canonicalized mix** is a sorted list of `[name, driver_kind, provider, system_prompt_sha256, model]` 5-tuples (sorted by `name` ascending), each tuple joined with U+001F (Unit Separator), tuples joined with NUL. `system_prompt_sha256` is SHA256 hex of the persona's system_prompt (empty-string hash for default personas). `model` is the resolved provider model after overrides. Tags are NOT included (cosmetic; don't affect output). Driver kind included so `cli-compat` and `http` against the same model still produce distinct keys.
- **Telemetry-leak warning fatigue:** if the warning fires every swarm run, users will tune it out. Mitigation — warn once per run, not per agent invocation; suppress with `--no-telemetry-warning`.
- **`cli-compat` becomes the path of least resistance** because it requires no protocol implementation: mitigation — order drivers in docs and `jutsu agent add` UX as `http > cli > cli-compat`; the `cli-compat` warning is intentionally noisy.
- **Goreleaser / brew tap regressions** from new package: mitigation — same release pipeline as v0.5; no new build-time dependencies (we keep it stdlib `net/http`, no SDK pulls).
- **`agents.yaml` and `kaijutsu.json` overlap confuses users** (both have `agents:` field): mitigation — `kaijutsu.json.agents` will be deprecated in v0.6 with a warning, removed in v0.7; loader reads new field with old as fallback.
- **Persona system prompts conflict with skill prompts.** Skill SKILL.md already supplies a system prompt. Persona prepends another. Order matters and may confuse models. Mitigation — explicit assembly order documented (`persona.system_prompt + "\n\n" + skill.system_prompt`); reference persona examples kept short and orthogonal; warn at swarm dispatch if combined system prompt exceeds 4KB.
- **MCP driver expands scope creep risk.** "MCP server as agent" opens a door (could become an LLM, a static analyzer, a fuzzer, anything). Mitigation — v0.6 ships with one reference integration (semgrep-mcp) and a tight contract (`analyze` tool, JSON findings array); explicitly NOT a generic MCP-tool-orchestration feature.
- **Prompt-cache "tax" on tiny prompts.** Padding to threshold means small swarms might pay more. Mitigation — D8 above; clear `CacheStatus: skipped-too-short` reporting.
- **`--estimate` rate cards go stale fast.** LLM pricing changes monthly. Mitigation — `rate_card_date` field; staleness warning >90 days; CI workflow on an upcoming v0.6.x release that auto-PRs rate updates from a vendored source.
- **MCP findings polluting the disagreement table.** A noisy semgrep config will dominate the synthesizer. Mitigation — MCP findings are pre-filtered by severity (info-level dropped before synthesis) and tagged `[deterministic]` for human triage.

### `AgentDriver` interface

```go
package agents

type AgentDriver interface {
    Name() string                 // user-facing name from agents.yaml ("claude", "deepseek")
    Driver() DriverKind            // cli | http | cli-compat | mcp
    Invoke(ctx context.Context, prompt string, opts InvokeOpts) (Result, error)
}

type DriverKind string
const (
    DriverCLI       DriverKind = "cli"
    DriverHTTP      DriverKind = "http"
    DriverCLICompat DriverKind = "cli-compat"
    DriverMCP       DriverKind = "mcp"
)

type InvokeOpts struct {
    Timeout time.Duration
    // No per-driver budget. Aggregate `--max-cost` enforcement lives in the
    // swarm pipeline (cli/internal/swarm/parallel.go); drivers report cost
    // via Result.CostUSD and the pipeline halts further dispatch when the
    // running total exceeds the budget. Per-provider caps are an explicit
    // non-goal for v0.6 (see Non-goals).
}

type CacheStatus string
const (
    CacheHit            CacheStatus = "hit"
    CacheMiss           CacheStatus = "miss"
    CachePartial        CacheStatus = "partial"
    CacheUnsupported    CacheStatus = "unsupported"
    CacheSkippedShort   CacheStatus = "skipped-too-short"
)

type Result struct {
    Raw         string
    CostUSD     float64
    Duration    time.Duration
    Driver      DriverKind   // populated by the orchestrator pre-dispatch; lets synthesizer/UI tag findings without re-lookup
    Err         string       // empty on success; populated string error message otherwise (matches v0.5 swarm.Result.Err)
    CacheStatus CacheStatus  // CacheUnsupported for cli/cli-compat/mcp; one of {Hit,Miss,Partial,SkippedShort} for HTTP
}
```

### Resolution

```
1. Load ~/.kaijutsu/agents.yaml          → globalCatalog map[string]Provider
2. Load <repo>/.kaijutsu/agents.yaml     → projectCfg{enabled []string, overrides map[string]Provider}
3. resolvedProviders := {}
   for name in projectCfg.enabled:
     base := globalCatalog[name]   (or builtin if absent)
     if name in projectCfg.overrides:
       base = base.Merge(projectCfg.overrides[name])
     resolvedProviders[name] = base

3a. resolvedPersonas := {}
    // Persona resolution (project ⊕ global ⊕ built-in):
    for name, p in builtinPersonas:
      resolvedPersonas[name] = p             // 7 built-in personas registered first
    for name, p in globalCfg.personas:
      resolvedPersonas[name] = p             // user global overrides built-ins
    for name, p in projectCfg.personas:
      resolvedPersonas[name] = p             // project overrides global
    // Auto-synthesize default-<provider> persona per resolved provider if not already declared:
    for name in resolvedProviders:
      if "default-" + name not in resolvedPersonas:
        resolvedPersonas["default-" + name] = {provider: name, system_prompt: ""}
4. for each resolved provider, look up api_key_env in os.Environ
   missing = []
   for name, p in resolved:
     if p.APIKeyEnv != "" && os.Getenv(p.APIKeyEnv) == "":
       missing = append(missing, name)
   if missing not empty: enforcement is path-dependent —
     - `jutsu swarm <preset>`: hard-fail with hint listing missing vars
     - `jutsu agent list`: warn (yellow), still print resolved table with missing keys flagged
     - `jutsu agent enable <name>`: warn-only (don't block enable; user may set env later)
     - `jutsu agent doctor`: this is the named UX — produces structured per-provider report, exits non-zero overall
5. construct AgentDriver per provider via DriverKind switch
6. hand registry to swarm pipeline, which calls driver.Invoke instead of agent.Run
```

## ROADMAP updates (v0.7 / v0.8+)

This spec mandates updating `ROADMAP.md` with the following entries during Stage 7. Listed here so reviewers see the full long-arc story this spec sits inside.

### v0.7 — committed targets
1. **Quality fingerprinting + confidence-weighted synthesizer.** Local SQLite at `~/.kaijutsu/findings.db` records user accept/dismiss per (provider, persona, preset, codebase-fingerprint) tuple. Synthesizer weights agent votes by observed precision/recall after ~50 runs. **The long-term moat.**
2. **Multi-stage swarm pipelines.** `jutsu swarm pipeline brainstorm-then-audit` chains presets with structured handoff. New `pipeline.yaml` DSL.
3. **Live TUI with streaming partial findings.** Each provider streams findings as they're generated; user watches progress in a terminal UI. Depends on streaming support landing in `http_driver`.
4. **Reverse swarm: spec-vs-implementation drift detector.** Run on every PR that closes a spec; flag deviations from declared scope/non-goals. Eats our own dogfood — the specs we're now writing become enforceable.
5. **Rule-based skip + skill-author skip-policy schema.** Deterministic heuristic gate (lockfile/comment-only/whitespace auto-skip), user-configurable in `agents.yaml` `skip_rules:`. Replaces the originally-considered Ollama 7B classifier (rejected: ~75-85% accuracy not worth ~30% CI savings against false-negative cost). Cheap-tier routing via existing v0.6 providers handles the bulk of cost reduction.
6. **Persona registry + `jutsu install persona:foo`.** Personas become installable artifacts. Requires registry-side schema work for non-skill artifacts.
7. **Per-skill provider routing.** Skills declare preferred personas/providers; swarm picks accordingly within enabled set.
8. **Per-provider retry policy** (5xx + 429 backoff with jitter).

### v0.8+ — speculative
- **Public anonymized swarm leaderboard.** Aggregate `{persona mix, preset, acceptance rate, cost}` stats; community sees what mixes outperform. Privacy + governance overhead is real; defer until usage signal warrants.
- **Agent-vs-agent debate mode (first-class).** Today's `--full` Pass-2 critique becomes a structured ranked-choice debate.
- **Skill DNA + auto-quality-test on publish.** Every `jutsu publish` runs the skill against a fixture corpus; quality metrics stored in registry. Lays foundation for the long-promised v0.1 eval gate.
- **Plugin drivers.** Third-party `.so` or sidecar process for non-HTTP-compat providers / custom orchestration.
- **Provider catalog from live registry.** `providers.json` fetched on first use instead of vendored in CLI binary. Trade-off: offline-first install vs. fresh provider metadata.

## ADR pointer

Architectural decision recorded separately at `docs/decisions/2026-05-05-driver-abstraction.md`. The decision: introduce a driver interface rather than per-call protocol switching, on the grounds that (a) the swarm pipeline already treats agents as opaque "give prompt → get raw output" boxes, (b) future drivers (plugin, sidecar) need a stable extension point, and (c) cli/http/cli-compat are genuinely different cost/leak/perf profiles that benefit from explicit naming.

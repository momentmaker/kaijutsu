# v0.15.0 — typed exit codes (minimal subset) + `jutsu finding export` upgrade

**Status**: draft
**Date**: 2026-05-09
**Branch**: `v0.15.0-exit-codes-export`

## Why

Two low-risk agent-ergonomics wins surfaced from parallel dream passes on the v0.14 post-ship candidate set (printing-press inspirations evaluated against project ethos):

1. **Typed exit codes — minimal subset only.** Today `jutsu` uses cobra defaults (0 success, 1 catch-all). Agents that wrap `jutsu` have to parse stderr to decide between "retry," "ask user for credentials," "abort." Standardizing a small, stable subset (0/2/3/4) lets agents branch on `$?` directly. The dream pass flagged shipping a *full* exit-code spec as contract-lock-in risk (5 lenses converged); the *minimal subset* defangs that risk by deferring the contested codes (5/6/7/8/9) until concrete user friction surfaces.

2. **`jutsu finding export --since --format jsonl` (stdout-friendly).** Today `jutsu finding export <path>` writes a single bulky JSON object to disk. Agents and shell pipelines want "give me last 7d of findings as JSONL on stdout so I can pipe to ripgrep / jq / my own LLM." The dream-pass inverse-lens pivot on the FTS5 candidate landed here: composability beats built-in search. Kaijutsu doesn't need to add a search engine; it needs to make the corpus exportable.

Both ship in v0.15.0 because they're orthogonal + complementary; sizing the surface kept small per stage 1 below.

## Locked decisions

| # | Decision | Choice |
|---|---|---|
| 1 | Exit code subset | Ship ONLY: `0` (success), `2` (usage error — bad flag, missing arg, mutually-exclusive flag combo), `3` (not-found — preset/persona/skill/agent missing from registry), `4` (auth — required env var unset, provider rejected creds at preflight). All other failures use `1` (catch-all). Defer 5/6/7/8/9 until lived experience surfaces a concrete need. Keeps contract lock-in surface ~minimal. |
| 2 | Public-contract status | Document the four codes in `AGENTS.md` + a new `docs/exit-codes.md` reference. Calling this a "documented contract" — future minor versions can ADD codes, must not RENUMBER or REPURPOSE existing ones. |
| 3 | Cobra error vs custom | Cobra emits exit 1 on any RunE error by default. Override via custom `os.Exit(code)` after RunE returns a wrapped error type. New internal `cli.ExitError{Code int; Err error}` — RunE returns it, root cmd unwraps + exits with code. |
| 4 | `finding export --since` | Accept duration in the same format as v0.14 `finding stats --since` (Nd / Nw / Nmo / Ny + std fall-through). Empty / unset = all-time. Negative / zero = error. Reuses `findings.ParseSinceDuration`. |
| 5 | `finding export --format` | Two values: `json` (default — back-compat with v0.7+ existing single-file behavior) + `jsonl` (one row per line, ideal for piping). Unknown value = exit 2. |
| 6 | `finding export` stdout target | Accept `-` as path argument to write to stdout, OR allow path to be omitted entirely when `--format jsonl` is set (jsonl is naturally streamable). Existing `finding export <path>` form unchanged. |
| 7 | Format invariants | `--format json` output schema = same as v0.7 (`schema_version: 1` + array of finding rows in one object). `--format jsonl` output schema = one finding row per line, no envelope, no schema_version line. CI gate added: round-trip jsonl → re-import → re-export equals original at the **logical-row level** (deep-equal compare on parsed Go structs, not byte-equal on JSON text). True byte-stability is impossible without a canonical JSON encoder; logical-row equality is sufficient for the data-recovery contract. |
| 8 | Marker bump | `init_agents_fragment` marker `0.14.0` → `0.15.0`. |

## Out of scope (defer)

- **Full exit-code matrix (5/6/7/8/9)** — dream flagged contract risk. Add when lived agent-wrapping experience surfaces "we needed exit code X for behavior Y" as a real friction signal, not preemptively.
- **Structured error JSON on stderr** (`{code, message, suggestion, retry-after, doc-url}`) — wild-lens 10x candidate from FTS5 dream. Strong idea; v0.16+ once we see how the typed exit codes get used.
- **`jutsu finding export --filter`** — would let users narrow further (codebase, preset, severity). Defer — `--since` covers 90% of the use case and existing `--codebase` / `--all-codebases` flags already filter on those axes.
- **FTS5 indexing of any kind** — replaced by the export pivot. If users start asking for in-place search after `export | rg` becomes the muscle memory, revisit then.
- **`--compact` mode** — flagged as a presentation-layer hack; the right shape is a future `--format` flag with multiple modes (e.g. `--format markdown|jsonl|compact`) on swarm-output commands. Defer entirely; don't ship the half-measure.
- **Compound finding queries** (`stale` / `health` / `bottleneck` / `reconcile`) — schema-versioning gap flagged in v0.14 dream; need usage data first.
- **`mcp serve` / `jutsu print` / `jutsu absorb` / `jutsu sync` / `jutsu observatory`** — all killed by v0.14 post-ship dream(s). See dream archives for rationale.

## Build sequence (single stage — small surface)

### Stage 1 — exit codes + export upgrade

**Goal**: ship a 4-code public contract + extend `jutsu finding export` with `--since` / `--format` / stdout. One-shot stage; no sub-phases.

**Files**:
- `cli/internal/cli/errors.go` — new `ExitError{Code int; Err error}` + helpers `UsageError(err)`, `NotFoundError(err)`, `AuthError(err)`. Each wraps an underlying error and carries a stable code.
- `cli/internal/cli/root.go` (or `cmd/jutsu/main.go`) — root cobra runner unwraps `ExitError` + calls `os.Exit(code)`. Generic errors continue to exit 1.
- `cli/internal/cli/finding.go` — extend `newFindingExportCmd`: add `--since`, `--format`, accept `-` as path or no path with `--format jsonl`.
- `cli/internal/findings/export.go` (new) — pure helper `ExportJSONL(w io.Writer, rows []Row) error` mirroring shape of existing JSON exporter.
- `cli/internal/cli/init_agents_fragment.go` — bump marker `0.14.0` → `0.15.0`.
- `docs/exit-codes.md` (new) — public contract reference.
- `AGENTS.md` (update) — link to `docs/exit-codes.md` + one-line summary.
- `CHANGELOG.md` — `[0.15.0]` entry.
- `ROADMAP.md` — flip v0.15 row.

**Surface mapping (which commands return which codes)**:

| Code | When | Examples |
|---|---|---|
| 0 | Command succeeded | normal completion |
| 2 | Caller-side mistake | `--by bogus`, missing required arg, `--json` + `--yaml` mutually exclusive, malformed `--since` |
| 3 | Lookup miss | `jutsu install foo` where foo not in registry; `jutsu swarm pr-review --personas no-such-persona`; `jutsu agent test deepseek` where deepseek not enabled |
| 4 | Auth/credential failure at preflight | required `<PROVIDER>_API_KEY` env var missing; provider rejected creds at the agent-doctor / preflight check |
| 1 | Anything else | I/O failure, network timeout, internal panic recovery, generic error, multi-model consent not granted (caller hasn't run `--grant-consent`; arguably code 2 in the future, but stays at 1 in v0.15 to keep the auth slot tight to provider-credential failures) |

**Refactor approach**: don't blanket-rewrite every error path. Add `ExitError` + helpers; convert known call sites where the right code is unambiguous (cobra's `MarkFlagsMutuallyExclusive` → 2; registry `Find` miss → 3; missing env in preflight → 4). Leave the long tail at `1` for now. Any future PR can convert specific paths as needed.

## Risks + mitigations

| Risk | Mitigation |
|---|---|
| Exit code contract lock-in (5 lenses flagged across both dreams) | Subset of 4 codes ONLY — minimum surface. Documented as a public contract that may ADD codes (never renumber/repurpose). Future codes earn their slot via concrete user friction, not preemptive coverage. |
| `jutsu finding export --format jsonl` to stdout breaks shells expecting file path | Path arg stays optional only when `--format jsonl` is set; the existing `<path>` form is fully back-compat. `-` as path is the explicit "stdout please" form. |
| jsonl output schema drift across versions | One row per line, no envelope. Each row = same shape as v0.7's array element. Schema-version contract sits at the json (envelope) form; jsonl is "row stream of v0.7 row schema." Document this explicitly. |
| Existing finding export consumers break on the new `--format` flag | Default `--format json` keeps existing behavior byte-stable. Round-trip CI test pins this. |
| Some `--since` formats accepted by `finding stats` may behave differently in `finding export` | Reuse `findings.ParseSinceDuration` — single source of truth. Tests pin both surfaces. |
| Adding `ExitError` wrapper everywhere = bloat | Don't blanket-rewrite. Convert obvious sites only (cobra mutual-exclusive groups → 2, registry-miss → 3, env-var-missing-at-preflight → 4). Long tail stays at 1. |
| Pre-alpha contract violation flagged in dream | Counter: documenting 4 stable codes is *less* invasive than ad-hoc agent stderr-parsing today. The "pre-alpha" framing on the landing page was already dropped in v0.14; calling jutsu pre-alpha while shipping v0.15 of a public CLI is the actual contradiction. |

## Notes carried forward (deferred but tracked)

- **Provenance receipt primitive** (from absorb dream): the source URL + commit SHA + run-id + finding-count + lens-blindspot-tags shape is a genuinely novel trust idea. Worth designing as a v0.15.x candidate that retroactively backfills receipts on the 22 already-vendored skills. Zero new fetch infrastructure; same trust-signal value.
- **NL→SQL over findings.db** (FTS5 dream wild-lens): "which auth bugs did claude miss but deepseek caught?" → translate to SQL → 50ms answer. v0.16+ candidate. Pairs with the export feature: once users have JSONL on stdout + the SQL query path, the corpus becomes genuinely conversational.
- **Compound finding queries** (`stale` / `health` / `bottleneck` / `reconcile`) — schema-versioning gap means we need usage data + a versioning plan first. Defer to v0.16+.
- **Structured error JSON on stderr** — natural follow-on to typed exit codes once they've earned their keep.
